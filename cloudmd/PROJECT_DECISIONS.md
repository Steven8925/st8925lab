## 一、專案由兩個獨立系統組成

規劃初期最大的認知調整:**這不是「一個網站」,是兩件不相干的事。**

```
① 公開作品集網站                    ② 家庭私密空間
   Astro + Cloudflare Pages            Nextcloud(現成軟體)
   全世界看得到                          裝在自家 NAS
   從零開發                             不用開發,裝現成的
   ↓                                   ↑
   網站上放一個連結 ─────────────────────┘
```

兩者**不共用程式碼、不共用帳號、不共用資料庫**。網站被攻破也碰不到家人的照片。

> **名詞澄清**:Nextcloud 是德國公司開發的開源軟體(可自架的私人版 Google Drive),不是本專案的自訂名稱。Nextcloud Talk 是它的附加模組,提供聊天與通話。

## 二、決策紀錄

### 2.1 定位與內容

| 項目 | 決定 | 理由 |
|---|---|---|
| **定位** | 專業作品集 / 能力宣傳,**少而精** | 目標讀者是企業客戶、SI、採購決策者、獵頭 |
| **紫微斗數 / 易經 / 八字** | ❌ **移出本專案** | 與 OT/IT 專業定位訊號衝突。買方掃過導覽的 5 秒內會形成「興趣廣泛」而非「能解決我的問題」的印象,這是實際的商業成本 |
| **金融市場分析** | ❌ 不公開發布 | 定位衝突 + 監理灰色地帶。留私密區自用 |
| **Blog / 最新文章** | ❌ 不做 | 更新停滯的 blog 對專業形象是負分。改用無時效壓力的 Reference |
| **通用開發工具**(CIDR、Base64、JWT、hash) | ❌ **刪除** | 與數千個相同頁面競爭不可能贏;更嚴重的是**稀釋主題權威**,讓演算法判斷你是「泛用開發者站」 |
| **導覽** | `Work` `Reference` `Tools` `Capabilities` `About`,**上限 5 項** | 超過 5 項不是少而精,是還沒決定重點 |
| **Case studies** | 4–5 篇,上限 6 | 4 篇有結構的案例勝過 20 個淺薄 demo |
| **APP 展示** | 截圖 + 短片 + 說明,**不掛 live demo** | 掛 live demo 等於同時維運 N 個應用 |

### 2.2 內容策略:兩個引擎

規劃中期最重要的結構變更。原本把五個區塊當對等並列,錯誤:

| | **流量引擎** | **轉換引擎** |
|---|---|---|
| 區塊 | Reference · Tools · Data | Work · Capabilities · About |
| 職能 | 被搜尋、被 AI 引用、被連結 | 把已到站的人轉成詢問 |
| 搜尋量 | 長尾穩定,競爭極低 | 幾乎為零 |

**串接規則(整份設計槓桿最高的單一項)**:每個 Reference / Tool 頁尾**必須**連到一篇 case study,連結文字要陳述因果——「這個位址偏移錯誤在一個實際案子中造成三天除錯 → 看完整案例」,不是「相關閱讀」。

沒有這條串接,兩個引擎各自空轉。

### 2.3 含金量從哪來

**不是寫作技巧,是別人沒有的東西。** 依可被抄襲難度排序:

1. **原始測量資料**(最高)— 實測相容性矩陣、實測輪詢效能、正規化廠商規格表。別人要複製必須重做一次工作
2. **具名可版本化的交付物** — `Modbus Integration Pre-Survey Checklist v1.2`。人連結「東西」,不連結「段落」
3. **失敗與診斷路徑** — 「我怎麼確定是位址偏移而不是接線問題」。網路上極度稀少,信任建立效率最高
4. **解決窄痛點的工具** — 每次計算要能產生可分享的 permalink
5. **可驗證的量化結果** — 附量測方法,否則數字沒有說服力

**灘頭陣地建議**:在既有機電設備上加裝 Modbus 監控。12 個月內在一個題目上做到全世界最好,勝過十個題目還可以。`[待確認]`

### 2.4 主機與部署

| 項目 | 決定 | 理由 |
|---|---|---|
| **Arvix 虛擬主機** | ❌ 不承載主要系統 | Shared hosting 的 ToS 多半禁止當檔案備份用、有 inode 限制、無法支撐 AI streaming 與長連線。可留作靜態 origin 用到合約結束 |
| **公開網站** | **Cloudflare Pages** + 私有 GitHub repo | 免費、不限頻寬、push 即部署、preview URL |
| **API 層** | **Cloudflare Workers** | 一次解決三件事:AI streaming、免費取得訪客地理資訊、無伺服器維運 |
| **私密空間** | **自家 NAS**,不上公網 | 見 2.6 |
| **月成本** | 約 **US$7–9** | Pages/Workers/Tailscale 免費 + R2 ~$1.5 + B2 ~$1–2 + AI API 上限 $5 |

### 2.5 技術選型

| 層 | 決定 | 被否決的選項與理由 |
|---|---|---|
| 前端 | **Astro**(全靜態)+ Tailwind + 極少 JS | ❌ React/Vue:INP 是本站最脆弱的指標,hydration 是主要風險來源。每頁 JS 預算 < 100KB |
| 後端 | **Cloudflare Workers**(TypeScript) | ❌ Django:shared hosting 走不動,serverless 架構下 TS 是阻力最小的路徑 |
| 資料庫 | **Cloudflare D1** + KV | ❌ PostgreSQL:在此架構是過度設計 |
| 內容管理 | **Git as CMS**(Markdown in repo) | ❌ 內容 DB:內容與程式同一份版本歷史,單人維運最省事 |
| Python | **退出主線** | 保留在本機:IoT 資料處理、彙總匯出、既有 Selenium pipeline |
| Repo | `site`(私有)· `api`(私有)· `modbus-tools`(公開) | 私有 repo → gitleaks pre-commit 從「建議」升為「必要」 |

### 2.6 私密空間

| 項目 | 決定 | 理由 |
|---|---|---|
| **軟體** | **Nextcloud**(不自寫) | 帳密管理 + 檔案總管 + 手機照片自動備份 + 分享,已是一套成熟軟體的完整規格。自寫檔案上傳的 path traversal 等漏洞踩雷率極高 |
| **為何非 Immich** | 一套系統同時滿足檔案 + 照片 + 多帳號 + 通訊 | 單人維運只顧一套。照片體驗不足時再疊 Immich |
| **存取方式** | **Tailscale**(對外零開放 port) | ❌ Cloudflare Access:與 native mobile app 的 SSO flow 相容性差,會卡住手機自動上傳 |
| **手機 App** | **PWA + Nextcloud 官方 app** | ❌ 自行開發原生 App:需求已被完全覆蓋,自建會吃掉一年空閒時間。PWA 唯一做不到的背景照片上傳,由 Nextcloud app 負責 |
| **即時通訊** | **Nextcloud Talk** + 自建 coturn | 訊息/通話/傳檔/離線留言全部原生支援。❌ 不部署 High Performance Backend(家庭規模不需要)。❌ 不開放給網站訪客——會從站長變成通訊平台營運者 |
| **Google 登入 + 2FA** | 由 Tailscale + Nextcloud 內建 2FA 取代 | 不需寫任何 auth 程式 |

### 2.7 NAS 配置(型號確認後)

| | **TS-473(A)-8G** | **TS-659 Pro II** |
|---|---|---|
| 狀態 | QTS 5.x,持續更新 | **QTS 4.2.6,已 EOL,永不修補** |
| 角色 | Nextcloud + Talk、Tailscale、備份中樞、IoT 收集器 | **純 LAN 內備份接收端,別無其他** |
| 網路 | 內網 + Tailscale | 不設 gateway/DNS + 路由器封鎖 → 物理上到不了網際網路 |

TS-659 因 EOL 存在永不修補的漏洞(QTS 4.x 正是 Qlocker/DeadBolt 世代的主要標的),唯一安全用法是完全隔離的單一用途裝置。但它讓 3-2-1 的第二份從「同機快照」升級為**真正的異機副本**。

**三層備份鏈**:TS-473A(即時 + 快照)→ TS-659(LAN 內異機,排程上電)→ Backblaze B2(client-side 加密,版本鎖定 ≥30 天)

### 2.8 安全與隱私

| 項目 | 決定 |
|---|---|
| **資料分級** | C0 公開 / C1 內部 / C2 私密 / C3 機密。分級決定能放哪個空間、要不要加密、怎麼備份 |
| **信任方向** | **NAS 只出不進**。網際網路上沒有任何東西能主動連進 NAS |
| **Secret** | 唯一合法位置是密碼管理器(Bitwarden 雲端版)。**刻意不自架 Vaultwarden**——與單人維運原則衝突 |
| **訪客分析** | 只存彙總 `(date, country, region, count)`,不存 raw IP。unique visitor 用每日輪替 salt 的 hash |
| **AI 助理** | Worker proxy(key 不進瀏覽器)· 月度硬性支出上限 · 只存結構化標籤不存逐字稿 · 保留 90 天 · **僅單一頁面且互動後才載入** |
| **網路工具** | 有對外連線的一律置於登入後(以權限分級取代黑名單,解決 SSRF 與濫用) |
| **去識別化** | 客戶名 → 產業描述;domain/IP/序號移除;EXIF 清除;**草稿不 commit**(Git history 永久) |
| **備份驗證** | 季度還原演練排進行事曆。**沒驗證過可還原的備份只是心理安慰** |
| **曝險自查** | 每季 Google dorks + crt.sh + Shodan + HIBP |

### 2.9 搜尋與 AI 可見度

**前提校正**:標記語法是門檻不是槓桿。權重約為 **技術標記 10–15% · 內容資產 50% · 站外連結與實體一致性 35%**。Astro 靜態輸出已達技術面天花板,做完只是**不因技術原因失分**。

| 項目 | 決定 |
|---|---|
| **工具頁結構** | 必須預渲染:定義句 → 答案優先段 → **至少 3 組靜態已解出範例** → 互動 widget → FAQ。空 div + JS 對 Google 與 AI 都是隱形的 |
| **寫作格式** | 定義先行(可被單獨抽取的句子)· 問答式標題 · 真實 `<table>` · 標註 `Last reviewed` 並真的複審 |
| **結構化資料** | Person(含 sameAs)· TechArticle · SoftwareApplication · **Dataset**(少人用且高度合適)· FAQPage |
| **雙語** | **關鍵字本地化,不是翻譯**。英文頁鎖 `modbus register address off by one`,中文頁鎖 `modbus 位址 40001 差一`,結論一致但不互為譯本 |
| **llms.txt** | 做,但不期待。Google 官方明示 Search 與 AI Overviews 不使用;第三方研究顯示 97% 從未被抓取。Perplexity/Claude 會讀 → 20 分鐘成本,當 agent 地圖 |
| **AI 爬蟲** | **允許** GPTBot/ClaudeBot/PerplexityBot。目標是被認識與被推薦,不是廣告流量 |
| **站外** | 沒有標記能勝過外部連結。公開 repo · 論壇真實完整回答(PLCtalk、r/PLC)· LinkedIn |
| **時程預期** | 0–3 月流量趨近零(正常,不要因此改策略)· 3–6 月長尾曝光 · 6–12 月首次 AI 引用與自然連結 |

### 2.10 設計

- **色票**:`#0A0E14` 底 / `#131A24` 表面 / `#2563EB` 主藍 / `#0F2A47` 深藍 / `#C9A227` 金 / `#E6EDF5` 文字
- **金色硬性規則**:不得用於正文(對比度過不了 WCAG AA)· 僅標題/分隔線/圖表 accent/hover · **面積 < 10%**

## 三、規劃過程中的重大轉折

| # | 原本 | 改為 | 觸發點 |
